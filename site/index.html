Firecracker sandboxes on the Kubernetes you already run.

By default, after 300 seconds without activity, loam pauses a sandbox, saves its memory and disk to your S3-compatible store and gives its VM memory back to the node. The next request restores its processes on a node with room. The official E2B SDKs are a familiar way in.

Install guide Source on GitHub

You run loam yourself, on x86_64 nodes with KVM. It is young, with one deployment so far, Jake Gaylor's three-node home cluster. The API server runs as a single replica, and there is no hosted service.

# point the E2B SDK at your loam
pip install e2b
export E2B_DOMAIN=e2b.loam.example.com
export E2B_API_KEY=loam_...
from e2b import Sandbox

sbx = Sandbox.create()
print(sbx.commands.run("uname -a").stdout)
sbx.pause()     # snapshot to S3, VM off the node
sbx.connect()   # wake it, processes intact

The official E2B Python and JS SDKs, unmodified, pass 26 of 26 conformance steps against loam, 13 each. That is the surface the adapter serves. Template builds are not supported. The full list is under E2B coverage.

How it works

Sleep and wake

A sandbox is a record in Postgres. No pod is created for it. Each KVM node you label runs one long-lived worker pod, the nodelet, which boots Firecracker VMs inside itself, owns their network and keeps a cache of snapshot layers on an XFS directory with reflinks.

When a sandbox goes idle, 300 seconds by default, the nodelet pauses it and uploads the dirty memory and disk blocks to your bucket. The VM is gone from the node and its memory is free for other work. The node still keeps a cache of its layers on disk. The next request wakes it on the node that has the snapshot locally, or on any node with room, with memory paged in lazily through userfaultfd. Waking never waits on the scheduler or etcd.

Pause, checkpoint and fork write the same layered format, so the native API can save a sandbox at a point in time and branch it. Firecracker is upstream v1.17.0. The components are in docs/ARCHITECTURE.md and the first steps in the primer.

E2B coverage

What the adapter serves

Set E2B_DOMAIN and E2B_API_KEY and the official SDKs talk to loam. Every E2B sandbox is an ordinary loam sandbox.

Supported

  • Create, get, kill, set timeout, and list with metadata and state filters
  • Commands and files through E2B's own envd (0.9.0) in the guest, with streaming and signed file URLs
  • Pause with memory or disk only, connect and resume, auto pause and auto resume
  • Sandbox ports at <port>-<id>.<domain>
  • The internet access toggle and allowOut and denyOut rules by name
  • Metrics as one sample, and health

Not supported

  • The template build API
  • E2B's snapshot and fork endpoints
  • Volumes
  • Sandbox logs and metrics history
  • CIDR and IP egress rules, since loam's rules are names only
  • secure:false and allowPublicTraffic:false, both refused

Checkpoints and forks exist in loam's native API. The full list and the differences from hosted E2B are in docs/E2B.md.

The boundary

What a sandbox can reach

The nodelet enforces the boundary outside the guest. The nodelet drops a VM's traffic to private address ranges, which on a typical cluster covers the node, the pod network and the LAN. Egress rules are names, exact or wildcard. The DNS forwarder refuses names outside the rules and strips private answers, and a transparent proxy on TCP 80 and 443 reads the Host or SNI, resolves the name itself and dials it, so another site on the same CDN address stays out. A sandbox with egress rules gets TCP over IPv4 only, and UDP, QUIC, ICMP and IPv6 are blocked.

Brokered secrets cover the hosts you configure them for. The sandbox's environment holds a placeholder and the nodelet substitutes the real value on the wire, so it never reaches guest memory, guest disk or a snapshot. A secret your application writes into the guest itself is its own business. A sandbox can ask its local socket for a short-lived JWT naming its project and ID, verifiable from outside.

The nodelet is unprivileged, with every capability dropped and eight added back, a read-only root and the default seccomp profile. The gap is cgroups. VMs share their nodelet's cgroup and its memory limit, with no cgroup per VM. Admission checks each nodelet's configured memory budget.

Run it

What you need

  • x86_64 nodes with KVM, so bare metal or an instance with nested virtualization
  • Linux 6.1 or newer on those nodes, for /dev/userfaultfd
  • A device plugin exposing /dev/kvm, /dev/net/tun and /dev/userfaultfd as resources
  • An XFS directory with reflinks on each node. An XFS image file on ext4 works
  • Postgres
  • An S3-compatible bucket
  • Wildcard DNS and a wildcard certificate for the API, port and E2B domains

k3s is what it runs on today. If that list fits, docs/INSTALL.md goes from the device plugin to your first key, with the kustomize base in deploy/base and an overlay of your own started from the example.

git clone https://github.com/arugula-salad/loam
cp -r loam/deploy/examples/basic my-loam
# set your domain, store URL, ingress and secrets in my-loam
kubectl kustomize my-loam | less
kubectl apply -k my-loam

The native CLI adds exec sessions, port URLs, checkpoints, forks, egress rules and brokered secrets.

go install github.com/arugula-salad/loam/cmd/loam@latest
export LOAM_API_URL=https://api.loam.example.com LOAM_TOKEN=loam_...
loam create scratch
loam run scratch -- uname -a
loam pause scratch
loam run scratch -- uptime     # wakes it first

To try it on one machine without a cluster, the Locally recipe in docs/E2B.md runs the nodelet in a container with /dev/kvm and loam-api with --database-url memory. That is a development setup, and the database goes away with the process.

Status

How it was built

The first commit was on 2026-10-11. loam has run one deployment since, a three-node home k3s cluster. It runs 17 browser games, a CI runner, a Signal agent and an E2B endpoint friends use. It was written mostly by Claude Code, working from Jake Gaylor's design and under his review. It is about 55k lines of Go, 18.5k of them tests. The snapshot store is about 12k lines copied and trimmed from e2b-dev/infra, Apache-2.0, with upstream Firecracker 1.17 in place of E2B's fork.

The open problems. loam-api is a single replica, so a restart briefly interrupts the API and the sandboxes' URLs. VMs share their nodelet's cgroup. It is x86_64 only. And the E2B gaps above.

Contribute

What would help

Install reports from clusters other than this one would help most, from Talos, kubeadm, a Hetzner or OVH bare-metal node, or nested virtualization on a cloud instance. After that, per-VM cgroups and the E2B gaps.

Bugs get fixed with a write-up of the cause. A sandbox moved to another node had no network for 30 seconds. Each node's bridge had a random MAC and the guest's ARP cache still pointed at the old gateway, so the bridge now has a fixed MAC everywhere. Headless Chrome could not get through the egress filter. Chrome sends ECH as GREASE on every connection and the proxy refused ECH, so it now judges by the outer name.

CONTRIBUTING.md has the setup. Report vulnerabilities privately as SECURITY.md describes.
